# ADR 004 — One bundle, many exporters; the HTML report is the flagship

**Status:** accepted · 2026-09-19

## Context

Ten export formats, each of which must contain the same disclosure block and the same
fact-versus-inference legend. Written naively, that is ten places to update when the
disclosure changes, and ten opportunities to disagree about what the project contains.

The interactive HTML report has an extra constraint: it has to open from a `file://` URL
on a machine that has never heard of API Galaxy, with no backend, no API key and no
internet connection.

## Decision

**One canonical `ReportBundle`, and every exporter is a pure function of it.**

```
AnalysedProject ──build_bundle()──▶ ReportBundle ──▶ html / pdf / print_html
                                          │          markdown / svg / png / mermaid
                                          │          jsonld / graphml / csv
                                   scope_bundle()
```

`scope_bundle()` narrows a bundle to the current view, one journey, one domain or an
explicit node set, and returns a *complete* bundle — disclosure, legend and methodology
intact. So a journey diagram and a whole-estate PDF carry the same provenance story.

## The HTML report

Self-contained, single file, read-only. Concretely:

* the data is one `<script type="application/json">` block, with `</script>` sequences
  neutralised so a schema named `</script>` cannot break out;
* the runtime is `packages/report-runtime/src/{report.js,report.css}` — plain ES2018 and
  plain CSS with **no build step**, inlined at render time;
* a `<meta>` CSP of `default-src 'none'; connect-src 'none'` makes the browser enforce
  what the code already promises;
* the DOM is built with `textContent`/`createElement`, never `innerHTML`, for anything
  derived from project data;
* it works: search, type and provenance filters, pan/zoom/fit, node inspector with
  provenance and evidence, clickable neighbours, journey playback with play/pause/step,
  legend, and a table fallback for screen readers.

### On "no external references"

A literal grep for `http` in the output is not a test we can honestly pass, because the
*user's own data* contains server URLs — NovaCart declares `https://api.novacart.example`
— and those appear as escaped text in the estate tables. Mangling the user's data to
satisfy a grep would be dishonest.

So the invariant is expressed as code instead: `external_references(document)` enumerates
every construct a browser would actually *fetch* — `<script src>`, `<link href>`,
`<img src>`, `url()`, `@import`, `fetch`, `XMLHttpRequest`, `WebSocket` — and the test
asserts it returns an empty list, plus that no `http` occurrence sits in an attribute
position. That is the real property; the grep was only ever a proxy for it.

## PDF

Generated by a reproducible HTML → PDF pipeline (WeasyPrint) from a **separate**,
print-specific HTML: static, no JavaScript, light palette, `@page` margins, CSS-counter
page numbers, controlled page breaks. Large estates get a structural overview plus one
focused diagram per domain, rather than one unreadable picture of everything.

**The PDF is static.** It is never described as interactive anywhere in the product.

## Optional dependencies

PNG needs `cairosvg`; PDF needs `weasyprint`. Both also need system libraries. When they
are missing, the format reports `available: false` with the reason, the UI greys it out
and shows that reason, and the API refuses it with an actionable message. It never
silently substitutes a different artifact.

A macOS wrinkle worth recording: Homebrew puts libcairo and libpango in `/opt/homebrew/lib`,
which `ctypes.util.find_library` does not search. `support.ensure_native_library_path()`
extends `DYLD_FALLBACK_LIBRARY_PATH` before the first import — the lookup is pure Python,
so it takes effect in-process with no relaunch.

## Consequences

* Adding a format is one function plus one registry entry; the disclosure comes for free.
* The disclosure block is defined once, so every artifact states project name, generation
  time, specification fingerprint, app version, active scenario, provider disclosure and
  the legend.
* Mermaid labels escape `<` and `>`. Mermaid renders labels as HTML by default, so a
  schema named `<script>` was an injection vector into whatever page displays the diagram.
